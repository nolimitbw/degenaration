## DO NOT REVERT — the design system, added 2026-08-11 in `530549b`

The interface was rebuilt to stop reading as machine-generated. Four things below look like
they could be tidied back to how they were. Each is load-bearing.

1. **`.ui-label` is sentence case, 12px, and not monospace.** The old treatment —
   `font-mono text-[9px] uppercase tracking-[0.08em]` — was applied 94 times across 33
   files, and four instances were at **8px**. Restoring it to any single label restarts the
   drift. New captions use `.ui-label`.

2. **Monospace means a machine string.** `.ui-code` is for wallet addresses, signatures,
   mints, correlation ids, version tags — things a user compares character by character.
   Numbers use `.ui-figure` (Archivo with tabular figures). Setting a timestamp, a count or
   a label in mono is the habit this replaced.

3. **Gold is spent once per screen**, on the primary action. Icons, dots, tab underlines,
   section headings and links are ink or muted on purpose. Making an icon gold "so it stands
   out" removes the only signal that says where to act.

4. **The absent marker is `—`, never `--` and never `0`.** `.ui-absent` renders it smaller
   than the figure it stands in for. `verify:responsive` asserts the em dash.

The label defaults sit inside `:where()` in `globals.css` so they carry zero specificity —
a caller that keeps an explicit `text-gold-400` beside `ui-label` still wins. Do not
"simplify" that by unwrapping the `:where()`; it would repaint every label in the product.

**`verify:responsive` asserts VALUES, not column headings.** It used to check for the
literal strings "Up now" and "Median now", which made renaming a column look like removing
a safeguard. It now asserts `72.2%`/`33.3%` and `1.42x`/`0.71x` — the peak/current pairing
that migration 10 exists to protect. Keep it that way; numbers cannot be renamed.

## DO NOT REVERT — decisions that look like bugs and are not

Each of these is deliberate, load-bearing, and covered by a test or a recorded reason.
Changing any of them re-breaks something that was fixed.

1. **The worker mirrors `PLATFORM_FEE_BPS` instead of importing `lib/fee-model.js`.**
   `render.yaml` deploys it with `rootDir: server`, so `lib/` does not exist at runtime.
   A cross-import would crash the deployed worker. A drift test fails if the values differ.

2. **`.app-shell` overrides the semantic colour tokens.** It scopes a slightly deeper gold
   (`185 139 93`) than `:root` (`194 148 99`). Collapsing them shifts every in-app surface.

3. **`toxic` / `hotpink` / `cyber` were removed from Tailwind on purpose.** They were named
   for a retired neon palette while holding warm gold values. Do not restore them; use the
   semantic names.

4. **`retained_fee_lamports` is a generated column.** Never write to it. The balance
   identity `creator + referral + retained === platform_fee` holds by construction.

5. **The `platform-allocation-offset` ledger entry must exist.** Without it the platform
   account is credited the gross fee while the creator is also credited, so a 200 bps fee
   produces 270 bps of credits and the ledger stops balancing.

6. **`body` is transparent; the canvas colour lives on `html`.** Moving it back to `body`
   hides `DegenBackdrop` behind it.

7. ~~**`copy.js` is deliberately still on the platform safety baseline.**~~
   **SUPERSEDED 2026-08-01 by `b15e66b` — do not restore this behaviour.** The reason it was
   deliberate no longer holds: `copy_subscriptions` now HAS `extended_config`
   (`supabase/degenaration-copy-execution-integrity.sql`), so there is per-bot config to
   honour, and `copy.js` resolves each subscriber's own filters inside the subscriber loop.
   It also claims atomically per detected buy. Reverting either would reintroduce the
   filter bypass and the multi-instance cap overspend. See OPEN_BLOCKERS B-2.

8. **The two Discord sources showing dashes is CORRECT.** Live DB: `raw_signals`=0,
   `market_snapshots`=0, `durable_jobs`=0. The worker has never run. Replacing dashes with
   values would be fabrication — §9.6 and §23 forbid it. Deploying the worker is the fix.

9. **`PLATFORM_FEE_ACCOUNT` is intentionally unset.** The owner's wallet
   (`FSF99fXB…`) is **not** a valid Jupiter `feeAccount` — it is a wallet, not a token
   account, and does not exist on chain. Setting it would make every swap fail at
   execution. Jupiter's API accepts any value without validating it, so "the API accepted
   it" is not evidence. See B-1.
