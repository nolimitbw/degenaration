## D-1 — MATERIAL. The creator commission has nobody to pay, and the card advertises it anyway

Both approved sources carry `creator_fee_bps: 70` and **`owner_privy_user_id: null`**:

| Source | Registered by | Owner linked | Creator fee advertised |
|---|---|---|---|
| SLPR DEGEN | `jaza777` | **null** | 0.70% |
| DegenAration | `degensalvador` | **null** | 0.70% |

`settle_execution_into_ledger` resolves the creator and then:

```sql
if v_creator is null
  or v_creator = v_intent.owner_privy_user_id
  or v_platform_fee <= 0 then
  v_creator := null;
  v_creator_bps := 0;
```

So on the first real Discord copy trade, the creator share silently becomes **0 bps** and the
whole platform fee is retained. No error, no warning. The two server owners earn nothing while
their marketplace card says *"0.70% creator commission included in 2% fee"*.

Corroborated by three tables that have never received a row: `discord_owner_link_sessions` = 0,
`discord_ownership_events` = 0, `source_ownership_history` = 0. **The owner-linking flow exists
and has never once been used.**

This is the same shape as the platform-fee defect fixed in `407b7b9` — the interface stating a
rate the execution path does not apply. It matters more, because someone else is owed the money.

**Fix has two halves.** The interface must stop promising a share that cannot be paid (mine, in
progress). The owners must complete the Discord link so attribution resolves (`/connect/discord`
→ `bot_create_discord_owner_link`) — that is an owner action, and until it happens the honest
display is "unassigned", not "0.70%".

## D-2 — Enabled safety filters would refuse every trade

`app_private.risk_snapshots` = **0** and `app_private.scanner_pools` = **0**.

The documented rule is fail-closed: *"When a required data source is unavailable, default to
fail-closed for enabled security filters."* With no holder or pool data, any bot with holder
concentration, sniper, bundler or LP-lock filters enabled refuses every candidate.

This is correct behaviour and it is also a trap: the day the worker comes up, a bot configured
with the default filter set may execute **nothing**, and the reason will look like "the worker is
broken" rather than "the risk provider has never populated". Worth knowing before the first
live test, not during it.

`scanner_tokens` (142) and `market_snapshots` (267) are now filling from the in-database price
scanner, so this gap is narrowing on its own — but risk and pool data come from a different
provider that nothing currently calls.

than claiming 2.00%. Does **not** need the fee wallet's private key. → `docs/ai/OWNER_RUNBOOK.md`.

## The limit nothing can fix retroactively

1,780 of 1,781 calls have **no `called_price_usd`**. The history backfill recovers the message
but not the market at that instant, so those calls can never show a *return* — only a current
price. Measured counts will climb from calls ingested live. The marketplace correctly counts
them unmeasured rather than inventing a baseline.
